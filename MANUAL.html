01

はじめる

GUIDE

WBS-GEN は、JSONまたはHTMLの内容を入力として、WBSとガントチャートを含む静的HTMLを生成・更新するローカルCLIツールです。このマニュアルは、GUIDE（1〜3章）でセットアップと日々の使い方を、REFERENCE（4〜8章）でコマンドと入出力JSONの仕様を扱う2部構成になっています。

JSON運用ではJSONを編集して generate でHTMLを新規作成します。HTML運用では script#wbsgen-source[type="application/json"] の埋め込みJSONをCLIで更新します。選んだ運用のデータだけを永続データとして更新し、画面・CSS・JavaScriptは派生物として再生成されます。ブラウザー編集、自動同期、競合処理は対象外です。

1.1

前提条件

  • Python 3.12 以上
  • モダンブラウザ（生成したHTMLの閲覧に使用します）
  • インターネット接続は不要です（祝日の自動取得は行いません）
1

ダウンロード

GitHub Releases から wbsgen.pyz とマニュアルを取得します。

2

プロジェクトJSONを作る

python3 wbsgen.pyz init my-project.json --name "個人開発プロジェクト"
3

HTMLを生成して開く

python3 wbsgen.pyz generate my-project.json -o output.html

output.html をブラウザで開くと、WBS表とガントチャートが表示されます。画面の説明は3章へ。

1.2

開発者向け補足

開発環境では .venv/bin/python -m wbsgen または .venv/bin/python wbsgen.py も同じサブコマンドで使えます。リポジトリのソースツリーから直接実行する場合は、事前に .venv/bin/python -m pip install -r requirements.txt を実行して openpyxl を導入してください。

02

日々の更新ワークフロー

GUIDE

正本は一方だけを選びます。JSON運用では編集後に検証・生成し、HTML運用ではHTMLだけを更新コマンドへ渡します。同じ内容を両方で並行編集しません。HTML運用のJSONバックアップには export json を使います。

2.1

CLIで更新する

タスクやプロジェクト、マイルストーン、休日の情報は、サブコマンドを使って1件ずつ追加・更新・参照・削除できます。よく使う操作の例は次のとおりです。

python3 wbsgen.pyz task add output.html --id 1.2 --name "実装"
python3 wbsgen.pyz task add output.html --parent-id 1 --name "実装"
python3 wbsgen.pyz task add output.html --name "リリース"
python3 wbsgen.pyz task update output.html --id 1.2 --progress 50 --dry-run
python3 wbsgen.pyz task show output.html --id 1 --direct
python3 wbsgen.pyz task show output.html --id 1.2 --complement
python3 wbsgen.pyz milestone add output.html --date 2026-07-20 --name "リリース判定"
python3 wbsgen.pyz holiday merge output.html --from holidays.json
python3 wbsgen.pyz project update output.html --status-date 2026-07-16
  • task add: --id でIDを明示するほか、--parent-id 1 で親1の直下へ、親未指定ならトップレベルへタスクを自動採番して追加します。
  • task update: ID 1.2 の進捗を50%に更新します。--dry-run を付けているため、実際には書き込まれず、変更内容の差分だけが表示されます。
  • task show: ID 1 のタスクの内容を確認します。--direct を付けると、表示される親・子タスクの範囲を直属の親子だけに絞ります（既定では祖先・子孫のすべてを表示します）。--complement を付けると、休日カレンダー考慮済みの計画終了日など、原本JSONに無い計算値を読み取り専用で確認できます。
  • task remove: ID 1.2 のタスクを子タスクごと（--recursive）削除します。こちらも --dry-run により、実際には削除せず対象を確認できます。
  • milestone add: 2026-07-20 に「リリース判定」というマイルストーンを追加します。ガント上には帯表示の◆マーカーとして反映されます。
  • milestone show: 登録済みのマイルストーンを日付順のJSONで確認します。
  • holiday add: 2026-08-10 を「会社休日」として入力JSON自身の休日に追加します。
  • holiday show: 登録済みの休日を日付順のJSONで確認します。
  • project update: プロジェクト全体の基準日（進捗計算などに使う日付）を更新します。

--dry-run を付けたコマンドは、ファイルに書き込まず差分表示だけを行います。内容を確認してから、--dry-run を外して再実行すれば反映されます。また、いずれの更新コマンドも、保存の直前にJSON全体が検証され、エラーがあれば書き込まれません。各サブコマンドの詳細な引数は4章を参照してください。

更新コマンドは入力HTMLを再生成し、同じパスへアトミック保存します。--dry-run は保存せず差分だけを示します。metadataなしHTMLは、初回更新または refresh で generatorVersion を追加して移行します。

2.2

エディタで直接編集する

プロジェクトJSONはテキストファイルなので、お使いのエディタで直接開いて編集しても構いません。複数のタスクをまとめて書き換えたい場合や、CLIの引数に対応していない細部を調整したい場合に向いています。JSONの書式（各フィールドの意味や必須項目）の詳細は5章を参照してください。エディタで編集したあとは、次のvalidateで内容を確認してください。

JSON運用では、最後に次の2コマンドで確認・生成します。

python3 wbsgen.pyz validate my-project.json
python3 wbsgen.pyz generate my-project.json -o output.html --overwrite
!
注意: generate は既存出力を上書きしません。明示的に置換する場合だけ --overwrite を付けます。検証エラーがある場合はHTMLを生成しません。
03

画面の見方

GUIDE

生成HTMLの画面は、上部のトップバーと、左右2ペイン（WBS表・ガントチャート）で構成されます。WBS表の下端には、生成日時・バージョンを示すフッターがあります。GitHubリポジトリ・マニュアルへの導線は、上部の☰メニュー内「WBS-GENについて」から確認できます。ここでは画面の各部と、ガントの色分けの意味を説明します。

3.1

画面レイアウト

図は、メニューと右下のウィンドウを閉じた標準状態です。左＝WBS表、右＝ガントチャートで、境界とタスク名列右端のハンドルをドラッグすると、それぞれ左右ペイン幅・タスク名列幅を調整できます（詳細は7.2）。右下には、検証の警告と休日を表示するウィンドウがあります。メニューの「表示」と「データ」、データ内の「JSON」「エクスポート」の操作は7.1を参照してください。

3.2

WBS表とガントチャートの見方

WBS表（左ペイン）には、次の列があります。

  • ID / タスク名: 常に表示されます。
  • 担当者: 入力JSONの assignee です。
  • 計画 / 実績: それぞれ開始日・終了日の期間です。
  • 進捗: 入力JSONの progress（0〜100）です。
  • 期待: 基準日時点で計画通りに進んでいた場合の期待進捗率です。
  • Issue / コメント: 入力JSONの issue / comment です。

ガントチャート（右ペイン）の要素は、次のように色で区別できます。

  • 子タスクの計画バー・進捗と、親タスク（集計行）の計画バー・進捗は、それぞれ異なる色調で表示されます。
  • 実績線は、計画バーとは別の色（濃紺）の線で表示されます。
  • イナズマ線は、基準日時点の進捗状況を折れ線でつなげて表示します。
  • 基準日は、縦のアンバーの破線で示されます。
  • マイルストーンは、日付ヘッダー直下の帯に◆マーカーと名前入りのピル、ガント全体を貫く縦の破線（赤系）で表示されます。近接した日付が重なる場合は、帯を上下2段以上に分けて表示します。
3.3

印刷・PDF保存

生成HTMLは、Chrome、Edge、Safariのブラウザの印刷から紙へ出力するか、「PDFとして保存」でファイルとして共有できます。印刷時には、プロジェクト名・表示範囲・基準日・凡例、WBS表、ガントチャートを出力します。

メニュー、標準／分析の切替タブ、検索、警告・休日の操作とウィンドウ、リサイズハンドル、ツールチップなどの操作UIは印刷されません。印刷開始時に選択中の標準または分析だけを出力し、折りたたみ、列表示、レイヤー表示もその時点の状態を反映します。

用紙サイズ、向き、余白、縮小率はブラウザの印刷ダイアログで選びます。ガントを横方向にページ分割したり、内容を必ず一枚に収めたりはしないため、必要に応じて用紙と縮小率を調整してください。

ガントの色・休日の塗り分けを出力するには、印刷ダイアログの背景の印刷（背景グラフィック）を有効にしてください。

3.4

遅延と警告の見え方

ガント上の遅延強調と、WBS表上の警告ハイライトは、別々の仕組みで表示されます。

  • 基準日時点で計画より進捗が遅れているタスクは、計画バーが同系色の枠線と影で強調されます。WBS表の「進捗」列のピルも、同じ条件でアンバー表示になります。
  • 進捗が100%のタスクは、計算上の遅延に関わらず遅延強調の対象外になり、完了を示す表示（グレー・取り消し線）になります。
  • 親タスク（集計行）の遅延強調は、子タスクとは異なる色調で表示されます。
  • 検証で警告が出たタスクは、タスク名セルがアンバーで強調されます（遅延強調とは別の仕組みです）。タスク名セルにカーソルを合わせると、警告コードがツールチップで表示されます。

遅延強調・警告ハイライトの操作方法や詳細設定は7.1を参照してください。

タスク追加task add INPUT_HTML --name NAME [--id ID | --parent-id PARENT_ID] [--assignee TEXT] [--planned-start DATE] [--planned-duration DAYS] [--actual-start DATE] [--actual-end DATE] [--progress 0-100] [--issue NUMBER] [--comment TEXT]

概要 HTML正本を更新する。

引数・オプション

  • INPUT_HTML — HTML正本。
  • --name — 必須。

制約・副作用

5.2

フィールド辞書

入力JSONの各フィールドを、オブジェクト別の表にまとめる。制約に反した場合に発生する検証コードは8章を参照。

project

フィールド型必須説明・制約
namestring必須プロジェクト名。空文字列・非文字列は不可（PROJECT_NAME_REQUIRED）。
startDatestring（YYYY-MM-DD）任意表示範囲の開始候補。endDate と両方指定した場合は、その期間を表示範囲の基準にする。形式が不正だと PROJECT_DATE_INVALID。
endDatestring（YYYY-MM-DD）任意表示範囲の終了候補。startDate と両方指定した場合のみ表示範囲の基準になる。どちらか一方が未指定なら、タスクの日付から自動で範囲を決める。
statusDatestring（YYYY-MM-DD）任意基準日。未指定の場合は実行日の本日日付を使う。表示範囲の外にあると PROJECT_STATUS_DATE_OUT_OF_RANGE（警告）。
issueBaseUrlstring任意task.issue からIssueリンクを作るためのベースURL。詳細は5.6。

tasks[]

フィールド型必須説明・制約
idstring必須WBS ID。1、1.2、1.2.3 のように、1以上の整数（先頭ゼロ不可）を . 区切りで表す。未指定・空は TASK_ID_REQUIRED、形式不正は TASK_ID_INVALID、重複は TASK_ID_DUPLICATED。parentId は使わず、親子関係は id の . 区切りで表す。
namestring必須タスク名。空文字列・非文字列は不可（TASK_NAME_REQUIRED）。
assigneestring任意担当者名。
plannedStartstring（YYYY-MM-DD）任意計画開始日。形式不正は TASK_DATE_INVALID。土日だと TASK_PLANNED_START_WEEKEND、holidays の休日と重なると TASK_PLANNED_START_NON_WORKING_DAY（いずれも警告）。詳細は5.3。
plannedDurationinteger任意計画日数。1以上の整数でなければ TASK_PLANNED_DURATION_INVALID。土日と holidays を除外した営業日数として扱う。リーフタスクで plannedStart と合わせてどちらかが未指定だと TASK_UNPLANNED（警告）。
actualStartstring（YYYY-MM-DD）任意実績開始日。形式不正は TASK_DATE_INVALID。
actualEndstring（YYYY-MM-DD）または null任意実績終了日。未完了タスクは省略または null。actualStart なしで指定すると TASK_ACTUAL_END_WITHOUT_ACTUAL_START、actualStart より前だと TASK_ACTUAL_END_BEFORE_ACTUAL_START。
progressinteger任意（既定 0）進捗率。0〜100の整数でなければ TASK_PROGRESS_INVALID。actualEnd があるのに100でないと TASK_PROGRESS_ACTUAL_END_MISMATCH、100なのに actualEnd がないと TASK_PROGRESS_COMPLETE_WITHOUT_ACTUAL_END。
issueinteger任意Issue番号。project.issueBaseUrl と組み合わせてリンク表示する。詳細は5.6。
commentstring任意補足コメント。

親タスク（子タスクを持つタスク）は、子タスクの集計結果として扱う。親タスクに plannedStart などの直接項目を指定しても、集計時には無視する（PARENT_FIELD_IGNORED、警告）。子タスクIDから推測される親IDが入力にない場合は、内部で自動補完する（MISSING_PARENT_TASK、警告）。

display

フィールド型必須説明・制約
standard.columns.visiblestring[]任意標準ビューで初期表示する列。assignee / planned / actual / progress / expected / issue / comment を指定する。* と -key による全表示・除外も使える。
standard.columns.widthobject任意標準ビューの幅可変列の初期幅（px）。name / assignee / comment をキーに、40以上の整数を指定する。
standard.columns.orderstring[]任意標準ビューの可動列の順序。assignee / planned-period / actual-period / progress / expected-progress / issue を部分指定でき、未指定列は既定順で末尾に追加する。
analysis.columns.orderstring[]任意分析ビューの可動列の順序。assignee / progress / expected-progress / delta / delay / pace を部分指定でき、未指定列は既定順で末尾に追加する。
layers.visiblestring[]任意ガント表示レイヤー。inazuma / actual / milestone / highlight / tooltip / delayHighlight を指定する。* と -key による全表示・除外も使える。

display 自体を指定する場合はオブジェクトにする。null や非オブジェクトは DISPLAY_INVALID。記法の詳細は5.4。

holidays[]

フィールド型必須説明・制約
datestring（YYYY-MM-DD）必須実在する日付。未指定・形式不正は HOLIDAY_DATE_INVALID。同一日付の重複は HOLIDAY_DATE_DUPLICATED。
namestring任意休日名。文字列でない場合は HOLIDAY_NAME_INVALID。

トップレベル holidays 自体が配列でない場合は HOLIDAYS_INVALID、要素がオブジェクトでない場合は HOLIDAY_REQUIRED。省略した場合は、従来どおり土日のみを除外する（後方互換）。詳細は5.5。

milestones[]

フィールド型必須説明・制約
datestring（YYYY-MM-DD）必須マイルストーンの日付。未指定・形式不正は MILESTONE_DATE_INVALID。
namestring必須マイルストーン名。空文字列・非文字列は不可（MILESTONE_NAME_REQUIRED）。

トップレベル milestones 自体が配列でない場合は MILESTONES_INVALID、要素がオブジェクトでない場合は MILESTONE_REQUIRED。同一の date と name の組が重複すると MILESTONE_DUPLICATED（警告）。表示範囲外の日付は MILESTONE_DATE_OUT_OF_RANGE（警告）になり、ガント上には表示されない。省略した場合はマイルストーン帯自体を表示しない。milestone サブコマンドでの操作は4章を参照。

5.3

日付と進捗の規則

  • plannedDuration は土日を除外した稼働日数として扱う。holidays を指定した場合は、そこに定義した祝日・会社休日・任意休日も合わせて除外する。
  • statusDate は画面上では「基準日」として表示する。
  • actualEnd はタスクの完了日である。
  • actualEnd がない未完了タスクでは、実績線を actualStart から基準日まで表示する。
  • actualEnd があるタスクは progress = 100 と合わせる。progress = 100 のタスクは actualEnd を入れる。両者が食い違う場合の検証コードは8章を参照。
5.4

display（初期表示の指定）

入力JSONのトップレベル（project や tasks と同階層）に置く display で、生成HTMLを開いたときの列とガント表示レイヤーの初期状態を指定できる。未指定の場合は、標準ビューの列とガントの各レイヤーをすべて表示し、列は既定順・既定幅で表示する。

"display": {
  "standard": {"columns": {
    "visible": ["*", "-comment"],
    "width": {"name": 260, "assignee": 70, "comment": 200},
    "order": ["progress"]
  }},
  "analysis": {"columns": {"order": ["delay"]}},
  "layers": {"visible": ["*", "-tooltip"]}
}

標準ビューの列表示

  • display.standard.columns.visible は、標準ビューの列の初期表示を指定する。指定できるキーは assignee / planned / actual / progress / expected / issue / comment。
  • ["*"] は対象カテゴリを全表示する。
  • ["*", "-comment"] は全表示から comment だけ除外する。
  • ["planned", "actual", "progress"] のように、指定したキーだけ表示することもできる。

除外記法 -key は * と一緒に指定する。["-comment"]、["*", "planned"]、[] は不正な指定であり、DISPLAY_INVALID になる。

標準ビューの列幅

display.standard.columns.width で、幅可変列（タスク名・担当者・コメント）の初期幅をpx単位で指定できる。生成後のHTML上でのドラッグによる列幅変更には影響しない（あくまで生成直後の初期表示幅）。

"display": {
  "standard": {"columns": {"width": {"name": 260, "assignee": 70, "comment": 200}}}
}
  • name / assignee / comment のいずれも省略可能で、一部のキーだけの指定もできる。省略したキーは既定幅（タスク名220px・担当者56px・コメント220px）になる。
  • 各値は40以上の整数（px）で指定する。40未満、非整数、負値、不正なキーは DISPLAY_INVALID になる。
  • タスク名列に極端に狭い値を指定し、かつ対象タスクの階層が深い場合、階層インデントの余白が列幅を超えてしまい、その行だけタスク名列とそれ以降の列がわずかに右へずれて表示されることがある。生成後にモックアップ等で見た目を確認することを推奨する。

列順

display.standard.columns.order と display.analysis.columns.order で、それぞれのビューの可動列の初期順序を指定する。どちらも部分指定でき、指定しなかった可動列は既定順で末尾に追加される。重複、未知のキー、固定列の指定、配列以外の値は DISPLAY_INVALID になる。

"display": {
  "standard": {"columns": {"order": ["progress", "assignee"]}},
  "analysis": {"columns": {"order": ["delay", "progress"]}}
}
  • 標準ビューで順序を指定できるのは assignee / planned-period / actual-period / progress / expected-progress / issue。ID・タスク名は左端固定、コメントは右端固定である。
  • 分析ビューで順序を指定できるのは assignee / progress / expected-progress / delta / delay / pace。ID・タスク名は左端固定である。
  • 標準ビューの表示・非表示と順序は独立している。非表示列も順序を保持し、再表示したときは指定位置に戻る。
  • HTMLの☰メニューで変更した列表示・列順は、そのHTMLを開いている間だけの操作であり、入力JSONやXLSXには書き戻さない。

ガント表示レイヤー

display.layers.visible は、ガント上のレイヤーの初期表示を指定する。指定できるキーは inazuma（イナズマ線）、actual（実績線）、milestone（マイルストーン）、highlight（行・日付のハイライト）、tooltip（ツールチップ）、delayHighlight（遅延強調）。配列の記法と制約は標準ビューの列表示と同じである。

display.analysis.columns.visible と display.analysis.columns.width は対応していない。分析ビューでは列の表示・非表示や幅の初期指定をせず、列順だけを指定する。

5.5

holidays と外部休日ファイル

休日はトップレベル holidays 配列に定義する。JSON運用では generate --holidays HOLIDAYS_JSON、HTML運用では holiday merge INPUT_HTML --from HOLIDAYS_JSON を使い、外部休日を日付単位でマージする。

"holidays": [
  {"date": "2026-06-08", "name": "会社休日"},
  {"date": "2026-07-20", "name": "海の日"},
  {"date": "2026-08-10"}
]
  • HTML運用の holiday add / holiday update / holiday remove / holiday show は、HTML正本の休日を操作・参照する。
  • 外部休日JSONファイルは、入力JSONと同じトップレベル holidays 配列を持つファイルである。フィールド定義は5.2の holidays[] 表と同じ。
  • 同じ日付は外部ファイルの値を優先し、異なる日付は追加する。validate と export xlsx に --holidays はない。
  • HTML生成時にインターネットへアクセスして祝日カレンダーを自動取得することはない。祝日を反映したい場合は、必ず holidays を自分で用意する。
  • 生成HTMLの埋め込みJSONには、マージ後の休日定義がそのまま保存される。
  • holidays を省略した場合は、従来どおり土日のみを除外する（後方互換）。

06

内閣府CSVからの休日取込

OPERATIONS

holiday import-gov report.html は、内閣府互換CSVから休日を取り込み、HTML正本を更新するコマンドである。入力JSONの仕様ではなく、明示した場合だけ外部通信を行う運用機能として扱う。generate 自体はネットワークへアクセスしない。

python3 wbsgen.pyz holiday import-gov report.html --dry-run
python3 wbsgen.pyz holiday import-gov report.html
python3 wbsgen.pyz holiday import-gov report.html --url https://www8.cao.go.jp/chosei/shukujitsu/syukujitsu.csv
python3 wbsgen.pyz holiday import-gov report.html --csv holidays.csv

既定URL以外の内閣府互換CSVを使う場合は --url URL を指定する（HTTPS限定）。取得失敗時は内閣府の「国民の祝日について」から手動取得したCSVを --csv PATH で指定する。--csv はネットワークを使用しない。

!
重要: 内閣府CSV取込の注意

import-gov は、このコマンドを明示した場合だけネットワークへアクセスする。既定URLは固定であり、ネットワークやプロキシの制限、内閣府側のURL・CSV形式・文字コード変更、将来分の掲載遅れにより取得できない場合がある。--url URL で取得先を変える場合もHTTPSに限られるため、接続先と取得内容を確認する。

取込前に --dry-run で差分を確認する。取得に失敗した場合は、手動取得したCSVを --csv PATH で指定する。取得・形式・再生成の失敗時もHTMLを変更しない。

07

生成HTMLの操作

REFERENCE

生成された output.html をブラウザで開くと、WBS表とガントチャートを確認できる。ここでは、表示の操作（7.1）、画面レイアウトの操作（7.2）、初期表示とURLクエリでの一時的な切り替え（7.3）について説明する。

7.1

表示の操作

トップバーのメニューは「表示」と「データ」に分かれます。「表示」では折りたたみ、列、レイヤーを切り替えます。「データ」には区切り線の下に「JSON」と「エクスポート」があり、JSONは埋め込み正本をダウンロードし、エクスポートは他形式の出力導線です。

行の折りたたみ・展開

  • 「表示」メニューの「▸ 折りたたむ」「▾ 展開」ボタンで、すべての行を一括で折りたたみ・展開できる。
  • 各親タスク行のツリートグルボタン（▾/▸）をクリックすると、その行の子タスクだけを折りたたみ・展開できる。

列の表示と順序

  • 標準ビューの「列」では、各列の表示チェックボックスで表示・非表示を切り替える。「すべて表示」「すべて非表示」は、ID と タスク名 以外の切り替え可能な列をまとめて操作する。
  • 担当者、計画、実績、進捗、期待、Issueの各行にある ↑ / ↓ を押すと、その列を左／右へ1つ移動する。メニュー内の行順とWBS表の列順は同時に入れ替わる。
  • ID と タスク名 は左端固定、コメント は右端固定である。コメントは表示チェックボックスだけを持ち、順序ボタンは表示しない。
  • 列の表示・非表示と順序は独立している。非表示にした列も順序は保持し、再表示すると元の位置に戻る。
  • これらの操作は開いているHTMLだけに反映され、入力JSONやXLSXには書き戻さない。初期状態を指定する方法は5.4を参照。

標準/分析ビュー

  • 「表示」メニュー上部のタブで「標準」「分析」を切り替えられる。分析ビューに切り替えると列構成が変わる。
  • 分析ビューでは、計画 / 実績 / Issue / コメント 列の代わりに、差分（計画に対する進捗のずれ）、遅れ営業日、必要ペース（期限までに間に合わせるために必要な1日あたりの進捗率。数学的に間に合わない場合は「未達」）の3列を表示する。
  • 担当者列は、標準ビュー・分析ビューのどちらでも表示される。
  • 分析ビューでは、列の表示チェックボックスと一括表示/非表示は表示しない。担当者、進捗、期待、差分、遅れ営業日、必要ペースの ↑ / ↓ だけで列順を変更できる。ID・タスク名は左端固定である。
  • 差分がマイナスのセルはアンバーで強調される。

ハイライト操作

  • WBS行、日付ヘッダー、ガント領域にホバーすると、対応する行・日付列・交差セルをハイライトする。
  • Ctrl または Command を押しながらクリックすると、ハイライトを固定する。
  • 固定済みの対象を Ctrl または Command を押しながら再クリックすると、そのハイライトを解除する。
  • Esc で固定ハイライトをすべて解除する（表示中のツールチップも閉じる）。

検索・フィルタ

  • トップバーの「検索 N件」ピルをクリックすると、検索条件のドロワーを開閉できる。
  • キーワードはタスク名、コメント、担当者、Issue番号を対象に、大文字小文字と前後空白を区別しない部分一致で検索する。Issue番号は #138 と 138 を同じものとして扱う。
  • 空白で区切った通常のキーワードはすべて一致するAND条件として扱う。各キーワードは、選択中の検索対象をまたいで一致してよい。たとえば、タスク名に「設計」、コメントに「レビュー」を含むタスクは、設計 レビュー に一致する。
  • 先頭に - を付けたキーワードは除外条件である。選択中の検索対象のいずれかに一致するタスクを除く。設計 -完了 は「設計」を含み「完了」を含まないタスクを検索し、-完了 は「完了」を含まないタスクを検索する。
  • OR条件、正規表現、引用符によるフレーズ検索、先頭ハイフンを通常文字として検索するエスケープは対応しない。
  • 「すべて」または個別の対象項目を選び、表示を「フィルタ」または「ハイライト」から選ぶ。フィルタでは一致行と祖先行だけを表示し、ハイライトでは全行を残して一致行だけを強調する。
  • 「条件をクリア」はキーワードと対象項目を初期状態へ戻す。表示モードは維持する。検索条件はこのHTMLを開いている間だけの状態であり、JSONやXLSXには書き戻さない。

ツールチップ操作

  • 「タスク名」「コメント」「担当者」は、省略されている場合だけ全文を表示する。
  • 「計画バー」はホバー時に、タスク名、計画終了、進捗、実績を表示する。
  • これ以外に、警告があるタスク名セル・行の折りたたみ／展開ボタン・リサイズハンドルには、ブラウザ標準のツールチップ（title属性）が用意されている。

レイヤーの表示切り替え

  • 「表示」メニューの「レイヤー」で、イナズマ線、実績線、マイルストーン、ハイライト、ツールチップ、遅延強調を個別に表示・非表示へ切り替えられる。
  • この切り替えは開いているHTMLだけに反映され、入力JSONやXLSXには書き戻さない。生成時の初期状態は5.4のdisplay.layers.visibleで指定する。

遅延強調

  • 基準日時点で計画より進捗が遅れているタスクは、計画バーを同系色の枠線と影で強調する。WBS表の「進捗」列のピルも、同じ条件でアンバー表示になる。
  • 進捗が100%のタスクは、計算上の遅延に関わらず遅延強調の対象外になり、完了を示す表示（グレー・取り消し線）になる。
  • 親タスク（集計行）の遅延強調は、子タスクとは異なる色調で表示される。
  • 遅延強調をOFFにしても、計画バーのツールチップでは遅延状態と期待進捗率を確認できる。

警告タスクのハイライト

  • 検証で警告が出たタスクは、タスク名セルがアンバーで強調される（遅延強調とは別の仕組みである）。
  • タスク名セルにカーソルを合わせると、そのタスクの警告コードがツールチップで表示される。
7.2

画面レイアウト

ペインのリサイズ

  • WBS表とガントの境界、タスク名列の右端にあるハンドルをドラッグすると、それぞれ左右ペイン幅・タスク名列幅を調整できる。
  • 広げられる幅には上限がある。
  • 調整した幅はページを再読み込みすると初期値に戻る（保存されない）。

固定ヘッダー・固定左ペイン

  • WBS表のヘッダー行とガントの日付ヘッダーは、縦スクロールしても常に表示され続ける。マイルストーン帯があるときは、日付ヘッダーの直下に含めて一緒に固定される。
  • WBS側の左ペインは、ガント側を横スクロールしても常に表示され続ける。
  • マウスホイールでの縦スクロールは、ペイン内のどこにカーソルがあっても画面全体のスクロールとして扱われる。

範囲外クリップマーカー

計画バーが表示期間の外にはみ出す場合、ガント領域の端に < / > のマーカーが表示され、表示期間の外にも続きがあることを示す。

ウィンドウ（警告・休日）

  • 検証で警告がある場合、警告ウィンドウが画面右下に自動で開いた状態で表示される。各警告のタスクID・コード・内容を一覧できる。
  • 入力JSONに holidays がある場合、休日ウィンドウが用意される（初期状態は閉じている）。トップバーの「休日 N件」をクリックすると開き、日付と休日名の一覧を確認できる。
  • 両方のウィンドウを開くと右下から左へスタックして並ぶ。「×」ボタンで閉じると、残ったウィンドウが詰めて配置し直される。
7.3

初期表示とURLクエリ

標準表示の指定（display）

入力JSONのトップレベル（project や tasks と同階層）に置く display で、生成HTMLを開いたときの標準表示を指定できる。未指定の場合は全表示になる。書式の詳細は5.4を参照。

"display": {
  "standard": {"columns": {"visible": ["*", "-comment"]}},
  "layers": {"visible": ["*", "-tooltip"]}
}

URLクエリでの一時的な表示切り替え

URLクエリでは、入力JSONの標準表示から一時的に隠す項目、および列順・列幅を指定できる。指定はページ表示だけに反映され、入力JSONやXLSXには書き戻さない。

output.html?hideColumns=comment,issue
output.html?hideColumns=assignee
output.html?hideLayers=tooltip,delayHighlight
output.html?hideLayers=milestone
output.html?hideColumns=comment&hideLayers=tooltip
output.html?standardOrder=progress,issue
output.html?analysisOrder=delta,pace
output.html?columnWidths=name:300,comment:200
output.html?keyword=設計%20レビュー%20-完了&fields=name,comment&mode=filter

keyword は検索欄の文字列をURLエンコードした検索条件である。空白区切りの通常語はAND条件、先頭 - の語は除外条件として復元される。fields は name/comment/assignee/issue のカンマ区切り、mode は filter または highlight を指定する。未指定または不正な項目は既定値（全項目、filter）として扱う。

standardOrder / analysisOrder は一部の列だけを指定でき、残りの列は入力JSONで確定している現在の表示順を基準に末尾へ補われる。columnWidths は name/assignee/comment のみ指定でき、key:value のカンマ区切りで指定する。未知の列キーや40未満の幅など不正なエントリは、その項目だけを無視して残りを適用する。

8.2

validate --json の出力

--json を付けない場合、検証メッセージ（エラー・警告）は wbsgen: warning TASK_PLANNED_START_WEEKEND tasks[2].plannedStart: plannedStart が土日です のような人が読む形式で標準エラーへ出力される（generate 実行時も同様）。

validate --json を使うと、検証結果を機械可読な JSON で取得できる。--json を指定した場合、人が読む形式のメッセージは標準エラーへも出力されない。

{
  "ok": true,
  "errorCount": 0,
  "warningCount": 1,
  "errors": [],
  "warnings": [
    {
      "level": "warning",
      "code": "TASK_PLANNED_START_WEEKEND",
      "path": "tasks[2].plannedStart",
      "message": "plannedStart が土日です"
    }
  ]
}

errors / warnings の各要素は、level（error または warning）、code（識別コード）、path（対象項目）、message（説明）を持つ。

個々のコードの一覧と発生条件は8.1を参照。

09

Excelエクスポート仕様

REFERENCE

export xlsx で出力されるXLSXファイルは、WBS シートと Info シートの2枚構成である。

  • Info シート: プロジェクト名、基準日、表示開始・終了日、入力ファイル名を記載する。
  • WBS シート: ID / タスク名 / 担当者 / 計画開始 / 計画終了 / 実績開始 / 実績終了 / 進捗 / 期待進捗 / 差分 / 遅れ(営業日) / 残り必要ペース / Issue / コメント の列に続けて、日付ごとのガント領域がある。

ガント領域は、計画期間をセルの背景色で、実績期間をマーク（■）で表現する。子タスクと親タスクで色味を変えて区別し、基準日の位置には縦の罫線を引く。土日・休日は背景色で塗り分けられる。

入力JSONに milestones が1件以上ある場合、日付ヘッダーの直下に「マイルストーン」行が追加され、以降の行は1行下がる。該当日の列には ◆名前 の形式でマーカーを表示し、縦の罫線（赤系、基準日の罫線とは別の色）を、基準日の罫線と同じ範囲（日付ヘッダー行から最終タスク行まで）に引く。同日に複数のマイルストーンがある場合は読点区切りで連結して表示する。表示範囲外の日付は表示しない。

--day-split {1,2,4} は、日付ごとのガント領域を1日あたり何列に分割するかを指定する。分割数が大きいほどマークの文字サイズが小さくなり、基準日の罫線がマークで隠れないように調整される。
